Problem — Operational Blindness in Complex Infrastructure
The issue is not just “too much data” —
but critical data is not visible when it matters most.
Telecom infrastructure is inherently complex, but the system forces users to remember instead of see
Tracing network issues takes time due to fragmented information across screens
Field teams, operations, and management operate on different

solution

Re-structured data to surface what truly matters at the right moment
Reduced fragmented screens into context-rich single views
Designed UI for visual scanning, not heavy reading
Integrated Map + Asset + Core network into one coherent mental model
Transformed network tracing into a seamless, continuous flow



MaxiTask is a system used by telecom teams to manage network infrastructure —
mainly by field engineers, operations, and planning teams who rely on it to search, trace, and make decisions quickly.
This project didn’t start with a goal to “make things look better.”
It started with a very simple problem:
Maxitask.com




The system was slow — and it was slowing people down.

Fixing Performance Through UX, Not Just Code

Instead of loading everything at once, I introduced a simple rule:
users must select an area first.
This reduced system load dramatically and made the map responsive again — especially on low-spec machines.

I began by talking to real users to understand how they actually use the system.
What I found was consistent across teams:

Everyone comes in to search first —
whether it’s to locate an issue, trace a fiber line, or check network connections.

But the system was forcing them to remember and navigate,
instead of helping them see and understand instantly.




Another important shift for me in this project
was learning how to think beyond screens.

For the first time, I had to break everything down into:

modules

pages

cases and states

actual tasks that could be handed to developers




In the end, the success of this project wasn’t just the new UI.

It was the fact that a system used for over 10 years
was replaced and accepted within 2 weeks.

The complaints faded in the first week.
And in the second week, people started saying:

Design is not finished until you know how it will be built — and when it will be done.

Option 2

A 2-minute scan of how I work.

Three things summarize my direction as a designer:

Pride, Dreams, and Lessons.

PRIDE
I redesigned telecom infrastructure data into a system people could scan, understand, and act on.

MaxiTask made me proud because I was not only redesigning a map interface. I was helping users work with complex telecom infrastructure — sites, fiber routes, core networks, copper networks, FTTx, microwave, customer layers, and operational records.

DREAMS
Designing UX for invisible infrastructure.

MaxiTask showed me that UX can make hidden national networks easier to understand, trace, and maintain.

LESSONS
Complex data needs recognition, not decoration.

I learned that users do not always need less data. They need better hierarchy, filtering, color memory, and context to find what matters quickly.
